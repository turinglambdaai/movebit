## 产品目的：提醒优先，角色其次

**MoveBit 始终是一款喝水、久坐起身、护眼微休息提醒工具。** 活跃工作检测、独立提醒周期、稍后提醒、暂停、历史与统计，才是核心功能。可爱的角色仅负责**呈现提醒和鼓励用户主动响应**，不是单纯做一只桌面宠物，更不做宠物养成或陪玩产品。

**北极星：** 让用户按时注意到清晰、可操作的喝水/起身/护眼提醒，同时不影响正常工作。优先级依次为：提醒准确与动作清晰、无打断与可控、视觉温度。不能为了宠物存在感主动创造与健康提醒无关的打扰，也不能把可爱动画视为用户真正喝水或休息的证明。

**典型场景：** 原有喝水提醒到期时，一个原创小角色在屏幕边缘举杯，配合简短清晰的喝水提示。用户可确认、稍后或隐藏；前台窗口不失焦，鼠标输入不受妨碍。这是在传递已有健康提醒，而不是索取宠物互动。

## 不可妥协的体验约束

1. **用户始终掌握控制权。** 旧版安装需主动选择开启宠物；原来的温和提醒保留。不能改写持久化的强制休息选择。全屏强制休息依旧单独启用，紧急退出独立有效。
2. **点击穿透。** 真实宠物交互区域以外，不得有透明但抢占鼠标事件的矩形窗口；不抢夺键盘焦点；即使后端失联，也可以隐藏/退出。
3. **默认靠边，活动范围有限。** 普通工作时不自动横穿屏幕中心。专注/演示模式停止移动和提示；自动检测必须有可信的系统支持，始终提供手动切换。
4. **一次到期，一次提示。** 原有 Racket 领域层已经合并同一 tick 的久坐、喝水和微休息事件；宠物动作也只能表达一次，但要完整保留所有到期类型，以免破坏稍后提醒与统计。
5. **不偏离健康提醒。** 无提醒时的待机动画是可选装饰；不引入独立陪玩、喂养、成长、惩罚、掉心情、未回应后的反复乞求，也不为了留存制造焦虑或宣称未经验证的健康效果。
6. **无障碍优先。** 支持系统减少动态效果、键盘和读屏等价操作、中英文提示。不能在没测过的系统上宣称功能完全一致。

## 首只宠物：行为与动作

| 已有健康事件 | 宠物行为（只用原创素材） | 操作 |
| --- | --- | --- |
| 喝水 | 举杯、轻轻抬头 | 完成、稍后、隐藏 |
| 微休息 | 眨眼、伸展、望远处 | 完成、稍后、隐藏 |
| 久坐 | 起身、邀请伸展 | 完成、稍后、隐藏 |
| 同时到期 | 一次组合动作，保留全部提醒类型 | 对所有到期类型正确处理 |
| 无提醒 | 默认安静，少量待机动画仅作为可选装饰 | 专注、隐藏；可选位置调整 |

MVP 表现状态：`idle`（待机）、`water`（喝水）、`stretch`（久坐活动）、`blink`（护眼）、`quiet`（静默）、`static`（减少动态效果）。可选短暂确认反馈。MVP 不做自主乱跑、宠物心情与陪玩模式。所有动作只是**后端健康提醒的视觉表达**，不是额外的事件来源。

## 提醒语义与成功标准

- `Due` 是后端认定提醒到期；`Shown` 表示真正显示；`Acknowledged` 表示用户回应；`Snoozed` 表示后端按周期延后。**确认不等于系统验证用户真的喝水或活动。**
- 同时到期的多种提醒必须保留全部类型，“稍后”应正确映射到原有后端。隐藏或静默不能伪造健康行为完成、增加完成次数、重置周期或默默丢弃待提醒事件；明确设计和测试暂缓/过期规则。
- 动作必须明确传递“喝水、站起来活动、看向远方”的其中一个健康建议，不能只放一个让用户猜意思的可爱图标。
- 应与既有温和 Toast 做对比：提示识别度、用户自述行动意愿、完成/稍后语义、烦扰程度、禁用比例、打断与抢焦点情况。可爱程度与互动时长是**次要指标**。

## 技术边界

- `racket/movebit/` 继续负责计时、提醒合并、安静/演示策略和动作意图，不允许三套宿主各自发明一套健康提醒器。
- 初始工程切片 `racket/movebit/companion-cue.rkt` 是**纯函数、尚未接入运行时**的提示映射：将已合并到期事件转成 `legacy | quiet | companion` 和动作。默认 `legacy`，测试保证合并顺序稳定、安静/减弱动画。它**暂时不实现**动画频率预算、全屏检测或提示窗口。
- `macos-host/`、`windows/`、`linux/` 负责原生透明窗口、命中区域、屏幕边缘停靠、拖动和动画。Wayland 等系统可能限制窗口定位和输入区域能力，必须如实记录，并回退为安全的静态宠物/托盘或原有温和提醒。
- 现有 `rivet-schema.json`、生成客户端、配置/历史和发布验收保持为唯一可信契约。RPC 变更必须同步三端和真实 wire/schema 测试。
- MVP 不为识别会议申请屏幕录制或系统辅助功能权限；隐私保持本地优先。迁移确认之前，新旧体验应可切换和回退。

## 开发、验收顺序

任务分阶段见 [#51](https://github.com/turinglambdaai/movebit/issues/51)。首要任务是**验证喝水/久坐/护眼提醒清晰有效且不阻断工作，而不是先堆宠物动画与养成机制**。三平台均需测试打字、鼠标选择与点击穿透、焦点恢复、多屏热插拔、缩放、休眠唤醒、全屏/演示、减少动态效果、读屏、后端崩溃、稍后提醒/离席重置与退出。

执行 `raco test racket/`、wire/schema 检查与 `raco rivet acceptance --json`（包含打包后的原生 UI）。只陈述已验证的平台和实测指标，不以某个平台测试通过代表三平台一致。公开产品文档继续保持中英文双份。
